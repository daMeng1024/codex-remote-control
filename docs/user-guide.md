# 用户手册

本文描述浏览器工作台中实际可用的操作。界面会根据 app-server 返回的数据动态变化，因此模型、权限和审批按钮可能与示例不同。

## 1. 登录与退出

打开部署地址后输入访问口令。登录成功会签发 12 小时会话 Cookie；Cookie 不会暴露给页面 JavaScript。

退出操作位于会话列表底部。退出会清除 Cookie，但不会停止 Codex 会话、managed app-server 或 systemd 服务。

## 2. 会话列表

列表每页读取 40 条会话，按最后更新时间倒序排列。每项显示：

- 会话名称或首条消息预览
- 工作目录
- 当前状态
- 最后更新时间

可用筛选：

| 控件     | 行为                                                |
| -------- | --------------------------------------------------- |
| 搜索     | 由 app-server 搜索会话内容或名称，最多输入 200 字符 |
| 状态     | `运行中`、`空闲`、`未加载`、`异常`                  |
| 已归档   | 在普通会话和已归档会话之间切换                      |
| 加载更多 | 使用 app-server cursor 追加下一页                   |
| 刷新     | 重新读取当前筛选条件下的第一页                      |

状态中的“待审批”和“待输入”优先于普通运行状态显示。

## 3. 打开现有会话

点击会话后，工作台 rejoin 该线程并读取最近 30 个 turn。更早的历史通过时间线上方的“加载更早记录”按 cursor 继续读取。

时间线支持：

- 用户消息和图片
- Codex Markdown/GFM 回复
- 可折叠 reasoning
- 执行计划
- 命令、工作目录、输出和退出码
- 文件变更与统一 diff
- 工具、子代理、网页搜索、提示和错误
- turn 运行状态

图片点击后在新标签打开。历史图片依赖网关临时附件；附件过期后会显示占位信息，而不会阻止文字历史读取。

## 4. 新建会话

点击“新建会话”并填写：

- **工作目录**：必须是允许根目录内已存在的绝对目录。
- **模型**：从 app-server 实时返回的模型列表选择，留空使用默认模型。
- **任务**：作为第一个 turn 的 prompt，不能为空，最多 50,000 字符。

新会话使用：

- `approvalPolicy=on-request`
- `approvalsReviewer=user`
- 非临时线程
- `threadSource=appServer`

创建成功后会自动进入新会话详情。

## 5. 发送消息

输入框支持最多 50,000 字符：

- `Enter` 发送。
- `Shift+Enter` 换行。
- 中文输入法组合期间按 Enter 不会误发送。
- 输入框随内容自动增高，最高约 140 px。

### 会话设置

输入框左侧的设置按钮可选择：

- 模型
- 协作模式
- 推理强度
- 权限配置
- Standard、Fast 或 Priority 服务层级

留空表示沿用当前会话或服务端默认设置。可选项来自 app-server；服务端没有提供的模型或权限不会显示。

这些设置应用到新的普通 turn。运行中的追加指令只携带文字、图片和目标 turn ID，不会在 steer 时重新切换模型或权限。

## 6. 发送图片

点击回形针按钮选择图片。约束如下：

| 项目       | 限制                             |
| ---------- | -------------------------------- |
| 格式       | JPEG、PNG、WebP                  |
| 单张大小   | 1 字节到 10 MB                   |
| 每次发送   | 最多 4 张                        |
| 服务端保存 | 随机文件名、`0600`、临时目录     |
| 清理时间   | 服务启动时清理超过 24 小时的附件 |

浏览器会先显示本地预览。发送时按选择顺序逐张上传，再将附件 ID 与文字一起提交给 Codex。服务端会同时检查 MIME、大小和文件签名，单纯修改扩展名不会绕过校验。

图片文件只用于当前主机上的 `localImage` 输入，不会成为通用文件上传接口。

## 7. 运行中追加指令与中断

当详情中存在 `inProgress` turn 时：

- 输入框占位文字变为“追加指令”。
- 发送按钮变为 steer 图标。
- 界面出现中断按钮。

追加指令通过 `turn/steer` 发送，并携带当前 `expectedTurnId`，防止把内容追加到已经变化的 turn。

中断调用 `turn/interrupt`。中断只作用于当前显示的活动 turn，不会删除会话和已有历史。

## 8. 重新编辑历史指令

用户文字消息旁有编辑按钮。点击后会把该条文字填回底部输入框并聚焦到末尾。

该操作不会修改历史消息，也不会回滚代码。编辑后发送会创建新的 turn；若当前 turn 正在运行，则会作为 steer 追加。

历史消息中的图片不会自动重新加入草稿，需要再次选择图片。

## 9. 审批与输入请求

待处理请求显示在审批抽屉中。多个请求可通过前后按钮切换。

支持的请求类型：

| 类型            | 展示内容               | 响应方式                     |
| --------------- | ---------------------- | ---------------------------- |
| 命令执行        | 原因、命令、工作目录   | 只显示 app-server 返回的决定 |
| 文件修改        | 原因和变更目标         | 只显示 app-server 返回的决定 |
| 权限申请        | 请求权限               | 本次允许、本会话允许或拒绝   |
| 用户输入        | 问题、选项或文本框     | 提交答案                     |
| MCP elicitation | MCP 消息与 schema 字段 | 提交、拒绝或取消             |

常见决定标签包括“允许一次”“本会话允许”“拒绝”和“取消任务”。命令规则或网络规则只有在 app-server 实际提供相应决定时才会出现。

处理前应检查：

1. 请求属于哪个会话。
2. 命令和工作目录是否符合预期。
3. 文件变更是否位于预期项目。
4. 权限是仅本次还是整个会话。
5. 输入框是否标记为 secret。

请求在以下情况会立即失效并从抽屉移除：

- 已在其他 Codex 客户端处理。
- app-server 发出 resolved 通知。
- daemon 连接断开。
- 当前页面提交成功。

重复响应或响应过期请求会返回 `409 Conflict`，不会静默重复执行。

## 10. 会话管理

详情标题栏提供：

- **分叉**：从当前最后一个 turn 创建新会话，并自动打开新会话。
- **重命名**：修改 Codex 会话名称，最多 100 字符。
- **归档**：从普通列表移到已归档列表。
- **恢复会话**：在已归档列表中取消归档。

首版不提供永久删除。归档不会删除 Codex 历史、工作区文件或附件。

## 11. 会话状态面板

桌面右侧检查面板显示：

- 状态
- 模型
- 服务层级
- 审批策略
- 权限配置
- 会话来源
- token 总量
- 上下文窗口使用百分比

token 和上下文数据只有 app-server 发送过使用量通知后才会出现。

## 12. 手机布局

窄屏采用两级导航：

1. 首屏显示会话列表、筛选和新建按钮。
2. 点击会话后切换到全屏详情。
3. 左上角返回按钮回到列表并 unsubscribe 当前会话。
4. 输入区固定在详情底部。
5. 审批抽屉覆盖在底部区域，处理后自动消失。

手机浏览器必须与主机加入同一个 ZeroTier 网络，并访问环境文件中配置的准确 Origin。页面打开不代表 WebSocket 一定可达，出现“实时连接正在恢复”时参考[故障排查](troubleshooting.md)。

## 13. 断线与恢复

浏览器 WebSocket 断开后按指数退避重连：从 500 ms 开始，最长 10 秒。浏览器保存最后事件序号，服务端最多保留最近 500 个事件。

如果事件已经过期、服务重启导致序号重置，服务端发送 `resync.required`，页面会通过 REST 重新加载：

- bootstrap
- 会话列表
- 当前会话详情

工作台没有后台通知。关闭浏览器后仍可由其他 Codex 客户端继续会话，但远程审批不会主动推送到手机系统通知栏。
